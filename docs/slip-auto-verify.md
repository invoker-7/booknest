# ตรวจสลิปโอนเงินอัตโนมัติ (ยังไม่เปิดใช้)

สถานะ ณ 8 ต.ค. 2026: โค้ดอยู่ใน branch `feat/e-slip` ยังไม่ได้ merge เข้า `main` เพราะยังไม่ได้สมัครบริการตรวจสลิป
เว็บจริงยังใช้วิธีเดิม คือเจ้าของร้านเปิดดูสลิปแล้วกด "ยืนยันรับเงิน" ที่ `/admin/orders`

## ทำไมถึงทำ

วิธีเดิมลูกค้าต้องรอร้านกดยืนยันทุกรายการ และสลิปปลอมหรือสลิปซ้ำจับได้ด้วยตาเท่านั้น
โจทย์ต้องการ "ส่งไฟล์อัตโนมัติหลังชำระเงิน" และร้านเลือกรับเงินผ่านพร้อมเพย์เพราะเงินเข้าบัญชีตรง ไม่ผ่านตัวกลาง
การตรวจสลิปด้วย API ให้ทั้งสองอย่าง: ลูกค้าได้ไฟล์ในไม่กี่วินาที และเงินยังเข้าบัญชีร้านเหมือนเดิม

## ทำงานอย่างไร

1. ลูกค้าสแกน QR พร้อมเพย์ โอนเงิน แล้วแนบรูปสลิป (ขั้นตอนเดิม ไม่เปลี่ยน)
2. เบราว์เซอร์เรียก `POST /api/checkout/slip/done`
3. ถ้าตั้ง `EASYSLIP_API_KEY` ไว้ server อ่านรูปสลิปจาก Storage แล้วส่งให้ EasySlip (API v2) ตรวจ
4. สลิปผ่านครบทุกข้อ ระบบบันทึกการชำระ ส่งไฟล์ และหน้าเว็บพาลูกค้าไปหน้าสั่งซื้อสำเร็จ
5. ไม่ผ่านข้อใดข้อหนึ่ง หรือตรวจไม่ได้ สลิปไปรอร้านตรวจในหลังบ้านเหมือนเดิม และร้านได้อีเมลแจ้ง

สลิปผ่านเมื่อ:

| เงื่อนไข | กันอะไร |
| --- | --- |
| ธนาคารยืนยันว่ามีรายการโอนนี้จริง | สลิปปลอม สลิปแก้ตัวเลข |
| เงินเข้าบัญชีที่ร้านลงทะเบียนไว้กับ EasySlip | สลิปที่โอนให้คนอื่น |
| ยอดตรงกับยอดรวมของคำสั่งซื้อพอดี | โอนไม่ครบ |
| EasySlip ยังไม่เคยเห็นสลิปใบนี้ | ใช้สลิปใบเดียวกับหลายคำสั่งซื้อ |
| เวลาโอนอยู่หลังเวลาสร้างคำสั่งซื้อ (เผื่อนาฬิกาต่างกัน 2 นาที) | เอาสลิปเก่าของรายการอื่นมาใช้ |

ลูกค้าไม่เห็นว่าไม่ผ่านเพราะข้อไหน เหตุผลถูกบันทึกใน log ของ server เท่านั้น (`slip ORD-…: <reason>`)

## ไฟล์ที่เกี่ยวข้อง

| ไฟล์ | หน้าที่ |
| --- | --- |
| `lib/slipVerify.ts` | เรียก EasySlip และตัดสินผล (`verifySlip`) |
| `app/api/checkout/slip/done/route.ts` | จุดที่เรียกตรวจ แล้วส่งไฟล์หรือแจ้งร้าน |
| `lib/slips.ts` | `readSlip` อ่านรูปสลิปล่าสุดของคำสั่งซื้อจาก Storage |
| `lib/apiClient.ts` | `uploadSlip` คืน `{ verified }` ให้หน้าเว็บ |
| `components/views/PromptPayView.tsx` | ถ้า `verified` ถามสถานะทันทีแทนการรอรอบถัดไป |

## สิ่งที่ต้องทำก่อนเปิดใช้

1. สมัครที่ https://developer.easyslip.com (ต้องยืนยันอีเมลและยืนยันตัวตน)
2. สร้าง Application แล้วเลือกแพ็กเกจ (ยังไม่ได้ตรวจราคา ดูในหน้านั้น)
3. ลงทะเบียนบัญชีธนาคารที่ผูกกับพร้อมเพย์ของร้าน (`PROMPTPAY_ID`) ในหน้าจัดการของ EasySlip
   ถ้าไม่ลงทะเบียน ระบบจะหาบัญชีที่ตรงไม่เจอ และสลิปทุกใบจะไปรอร้านตรวจเอง
4. ไม่เปิด IP whitelist เพราะ Vercel ไม่มี IP ตายตัว
5. ตั้ง `EASYSLIP_API_KEY` ใน Vercel (Settings > Environment Variables) แล้ว redeploy
6. merge branch `feat/e-slip` เข้า `main`
7. ทดสอบด้วยการซื้อจริงยอดเล็ก ๆ หนึ่งรอบ แล้วดู log ใน Vercel

ไม่ตั้ง `EASYSLIP_API_KEY` ระบบทำงานแบบเดิมทุกอย่าง โค้ดนี้จึง merge ได้ก่อนสมัครโดยไม่มีผลกับเว็บ

## ทดสอบแล้วแค่ไหน

- ทดสอบแล้ว: ตรรกะตัดสินผลใน `verifySlip` กับบริการจำลอง 12 กรณี ได้แก่ ผ่าน, สลิปซ้ำ, ผิดบัญชี, ผิดยอด (สองแบบ), สลิปเก่า, ไม่มีวันที่, สลิปปลอม, โควตาหมด, บริการตอบ 500, รูปเกิน 4 MB และต่อบริการไม่ได้
- ยังไม่ได้ทดสอบ: route `slip/done` ทั้งเส้นตั้งแต่แนบสลิปจนส่งไฟล์ และการเรียก EasySlip ตัวจริง
  รูปแบบคำขอและคำตอบเขียนตามเอกสาร https://document.easyslip.com/en/v2/ ถ้าของจริงต่างจากเอกสาร ผลคือสลิปไปรอร้านตรวจเอง ไม่ใช่ปล่อยไฟล์ผิด

ทดสอบในเครื่องโดยไม่เรียกของจริงได้ด้วยการตั้ง `EASYSLIP_API_URL` ให้ชี้ไปที่ตัวจำลอง (ใช้เฉพาะตอนทดสอบ ห้ามตั้งบน production)

## ข้อจำกัดที่รู้อยู่

- รูปสลิปใหญ่เกิน 4 MB ตรวจอัตโนมัติไม่ได้ (เว็บรับสลิปได้ถึง 5 MB) จะไปรอร้านตรวจ
- สลิปธนาคารกรุงเทพบางครั้งตรวจได้ช้า EasySlip ตอบ `SLIP_PENDING` ซึ่งตอนนี้ถือว่าตรวจไม่ได้และไปรอร้านตรวจ ยังไม่มีการลองซ้ำ
- ตะกร้าหลายชิ้นจ่ายด้วยสลิปใบเดียว ระบบตรวจสลิปของคำสั่งซื้อแรกในชุดเทียบกับยอดรวมทั้งชุด
- ถ้าตรวจผ่านแล้วแต่ขั้นส่งไฟล์ล้มเหลวกลางทาง การเรียกซ้ำจะถูกมองว่าสลิปซ้ำ ร้านต้องกดยืนยันเองในหลังบ้าน

## งานที่ต่อยอดได้

ทำได้โดยไม่ต้องพึ่งบริการภายนอก และช่วยทั้งการตรวจเองและการตรวจอัตโนมัติ:

- คำสั่งซื้อหมดอายุเมื่อไม่จ่ายภายในเวลาที่กำหนด หลังบ้านจะไม่มีรายการค้าง
- จำลายนิ้วมือ (hash) ของไฟล์สลิป เตือนร้านเมื่อใบเดิมถูกแนบกับคำสั่งซื้ออื่น
- เติมเศษสตางค์ให้ยอดแต่ละคำสั่งซื้อไม่ซ้ำกัน ร้านจับคู่เงินเข้ากับคำสั่งซื้อได้แม้ไม่ดูสลิป
- แสดงผลการตรวจอัตโนมัติ (เหตุผลที่ไม่ผ่าน) ให้ร้านเห็นในหน้า `/admin/orders` แทนการดูจาก log
- ลองตรวจซ้ำอัตโนมัติเมื่อได้ `SLIP_PENDING`

ทางเลือกอื่นถ้าไม่ใช้ EasySlip: SlipOK (แนวเดียวกัน ต้องแก้เฉพาะ `lib/slipVerify.ts`) หรือ payment gateway ที่แจ้งผลผ่าน webhook เช่น Opn หรือ Stripe ซึ่งไม่ต้องใช้สลิปเลย แต่ต้องยืนยันตัวตนและเงินเข้าช้ากว่า
